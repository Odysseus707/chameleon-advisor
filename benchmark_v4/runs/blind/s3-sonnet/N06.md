import chi
from chi import lease, container

chi.use_site("CHI@Edge")
chi.set("project_name", "CHI-000000")

# Create and start the lease using the object-oriented API
my_lease = lease.Lease("demo-lease", duration=dict(days=0, hours=10))
my_lease.add_device_reservation(machine_name="raspberrypi4-64", count=1)
my_lease.submit(wait_for_active=True)

# Create the container using the reservation tied to the lease
my_container = container.Container(
    name="demo-app",
    image_ref="python:3.9-slim",
    reservation_id=my_lease.device_reservations[0]["id"],
    exposed_ports=[22],
    platform_version=2,
)
my_container.submit()
A few notes on the translation:

lease.create_lease(...) + lease.wait_for_active(...) collapse into lease.Lease(...) construction followed by .submit(wait_for_active=True), which blocks until the lease is active (equivalent to the old wait_for_active call).
lease.lease_duration(days=0, hours=10) is replaced by passing duration=dict(days=0, hours=10) directly to the Lease constructor — the object computes start/end dates internally.
lease.add_device_reservation(res, ...) becomes a method on the lease object itself: my_lease.add_device_reservation(...), which appends to my_lease.reservations internally.
lease.get_device_reservation(l["id"]) is replaced by reading the reservation ID directly off my_lease.device_reservations[0]["id"], since the object caches reservation info after submission (no extra API round-trip needed).
container.create_container(...) becomes container.Container(...) + .submit(), mirroring the lease pattern — construct with the same keyword arguments (name/image_ref instead of positional name/image), then explicitly submit.

The overall behavior is identical: reserve a Raspberry Pi 4 device for 10 hours, wait for the lease to go active, then launch a python:3.9-slim container on it with port 22 exposed.
