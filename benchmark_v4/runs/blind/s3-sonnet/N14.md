For CHI@Edge on Raspberry Pi, USB audio capture takes a bit of setup because the container needs access to the host's ALSA device. Here's how to approach it.
Device profile
CHI@Edge uses a JSON device profile to define hardware access. For USB audio, you need to expose the ALSA device node to the container. Something like:
json{
  "device_profiles": [
    {
      "name": "usb_audio",
      "devices": [
        {
          "path": "/dev/snd",
          "type": "audio"
        }
      ]
    }
  ]
}
The key point: /dev/snd is the ALSA device directory on the host Pi, and it needs to be passed through (not just /dev/snd/pcmC0D0c or similar, since USB mic card numbers can shift between boots — mounting the whole directory is more robust).
Container setup

Base image: use a Debian/Ubuntu-based image with alsa-utils installed (or install it in your Dockerfile):

dockerfileFROM python:3.11-slim
RUN apt-get update && apt-get install -y alsa-utils sox

Device mount: when launching the container on CHI@Edge, request the device profile above so /dev/snd is bound in.
Group permissions: the audio device on the Pi is usually owned by the audio group. Inside the container, either run as a user in a matching audio group, or run privileged enough to read /dev/snd/* — check permissions with:

bashls -l /dev/snd
and match GIDs if needed, since container and host GID mapping doesn't always line up automatically.

Verify capture device: once inside the container, confirm the mic is visible:

basharecord -l
This should list your USB mic as a card (e.g., card 1: Device).

Record test:

basharecord -D plughw:1,0 -f cd -d 5 test.wav
Adjust the plughw:X,0 card number to match what arecord -l reports — USB mics often aren't card 0 since the Pi's onboard audio (if any) takes that slot.
A couple of gotchas specific to CHI@Edge

Not all CHI@Edge node types support arbitrary device passthrough — this depends on the k3s/containerd device plugin config on that particular Pi cluster. Worth checking the Chameleon docs or the CHI@Edge-specific device profile examples in their GitHub, since exact syntax has shifted across versions.
If /dev/snd passthrough isn't permitted by the node's security policy, you may need to fall back to a privileged container, which not all CHI@Edge deployments allow for end users.
