To reserve the device `iot-rpi-cm4-02` with the Waveshare Sense HAT (B) and launch a sensor container configured to work with GPIO libraries despite missing devicetree info inside containers, follow these steps:

1. **Reserve the Device**: Reserve `iot-rpi-cm4-02` for 4 hours using the CHI@Edge platform.

2. **Launch the Container**:
   - Use the image `ghcr.io/chameleoncloud/edge_sensehat_image:latest`.
   - Ensure that the container is launched with the `pi_gpio` device profile to expose necessary `/dev` devices.
   
3. **List I2C Bus Devices**: Once the container is running, you can list what's on the I2C bus by executing a command inside the container.

Here’s how you might do it step-by-step:

### Step 1: Reserve the Device
You would typically use the CHI@Edge reservation system to reserve `iot-rpi-cm4-02` for your experiment. This can be done through the Chameleon Cloud portal or via an API call, depending on your workflow.

### Step 2: Launch the Container
Once reserved, you need to launch a container with the specified image and device profile:

```bash
# SSH into the reserved node (iot-rpi-cm4-02)
ssh user@iot-rpi-cm4-02

# Pull the required Docker image
docker pull ghcr.io/chameleoncloud/edge_sensehat_image:latest

# Run the container with the pi_gpio device profile to expose GPIO devices
docker run --device /dev/i2c-1:/dev/i2c-1 --name sensehat_container -itd ghcr.io/chameleoncloud/edge_sensehat_image:latest
```

### Step 3: List I2C Bus Devices
After launching the container, you can list devices on the I2C bus by running a command inside the container:

```bash
# Attach to the running container
docker exec -it sensehat_container /bin/bash

# List I2C devices
i2cdetect -y 1
```

This will display a table of addresses and device IDs for all devices connected on the I2C bus.

By following these steps, you ensure that the GPIO libraries work correctly within the container despite missing devicetree information.
