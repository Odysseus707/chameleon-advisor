# Harness plan: scripted benchmark runs against the fork (and API models)

**Phase A deliverable** — confirms the run-prompt format, the exact layout the scorer
consumes, and the headless hook point into the fork's answer pipeline. Implemented by
`benchmark_v4/tools/run_bench.py` (Phase B) and its `--pilot` mode (Phase C).

---

## 1. Run-prompt format (confirmed)

Generated by `benchmark_v4/tools/make_run_prompts.py` into `prompts/<condition>/<ITEM>.txt`
(one plain-text file per item × condition; no JSONL or notebook-cell variant —
`tools/v3_prompts.jsonl` is the legacy v3 item bank, not a run-prompt format).

- **blind**: the item's `prompt` field verbatim, nothing else.
- **matched / heldout / uncovered** (`make_run_prompts.py:23-41`):
  ```
  Here is reference material about CHI@Edge on Chameleon Cloud that may be relevant to my question.
  === REFERENCE MATERIAL ===
  <grounding/<A#>.md files, joined by blank lines, in fed_sets order>
  === END REFERENCE MATERIAL ===

  Question: <prompt>
  ```

## 2. The exact layout the scorer consumes (confirmed)

```
runs/<condition>/<system>/<ITEM>.md
      blind|matched|heldout|uncovered   s1-chatbot|s2-gpt|s3-sonnet|s4-fork-on|s5-fork-off|...   P01..N18..AV04
```

The only batch scorer ("recalc") is the cell in `notebooks/validate_golds.ipynb`:
`glob.glob('runs/*/*/*.md')` then `_, cond, system, fname = path.split(os.sep)` — which
hard-requires **exactly three path levels** under `runs/` and filename stems that match
`items/<stem>.yaml`. Single-item scoring: `python -m harness.runner --item items/X.yaml
--answer <file>.md` (snapshot defaults to `snapshots/snapshot_synthetic_2026-07-04.json`).

Rules a runner must obey:
- **Preserve code fences.** `harness/runner.py:26-39 extract_code()` regex-extracts
  ```` ``` ```` blocks (fallback: the whole text only if it `ast.parse`s). The 50
  hand-pasted answers lost their fences on copy — the κ≈0 calibration problem — so the
  runner writes raw model output verbatim, fences intact. Never strip prose: prose outside
  fences is harmless to the extractor and is part of the record.
- **Sidecars are invisible to the scorer.** Anything not `*.md` (telemetry JSON,
  `manifest.json`) can live in the same directories safely.
- **Never modify saved responses.** Existing non-empty `.md` files are never overwritten
  (no force option); 0-byte scaffold placeholders may be filled — that is their purpose.
- Empty files score FAIL without crashing; nothing under `harness/` or `notebooks/` changes.

## 3. Headless hook into the fork (confirmed)

`web_rag.py` **cannot** be imported headless: the whole app is module-top-level Streamlit
(`st.set_page_config` at import, `st.stop()` if `vect_store/` is missing). The full answer
pipeline is instead composed from pure parts, exactly as the existing half-precedents do
(`m2_smoke.py` = RAG half, `eval_m4.py` = advisor half):

```python
from rag import load_vectorstore, load_parents, create_llm_chain, build_context
import advisor_room as ar                      # needs chi-edge-advisor on sys.path

vs, parents, chain = load_vectorstore(), load_parents(), create_llm_chain()   # once
srcs, ctx, _ = build_context(q, vs, parents)                                  # per item
if advisor_enabled and ar.should_fire(q, gate):                               # gate
    ctx += "\n\n=== EDGE RESOURCE ADVISORY ===\n\n" + ar.advise(q)            # exact web_rag inject (web_rag.py:472-474)
answer = chain.invoke({"question": q, "context": ctx, "history": []}).content
```

- LLM config is env-driven (`rag.py:15-16, 213`): `LLM_API_BASE`, `LLM_API_KEY`,
  `LLM_MODEL`. On the node these point at local Ollama (`http://localhost:11434/v1`,
  `qwen2.5:32b-instruct-q4_K_M`); the advisor's reasoner uses `LLM_PROVIDER=tejas` at the
  same endpoint (see `node.env.reference`).
- `advisor_room.get_room()` asserts the bge embedder and loads
  `chi-edge-advisor/data/artifact_store.json` — both satisfied on the node.
- Telemetry per item, without touching production code: `ar.classify_top(q)` (gate score),
  `should_fire` (fired bool), retrieval source URLs from `build_context`, the advisory text,
  and `grounded_by=[...]` / `produced_by=(\w+)` parsed from it (eval_m4's regexes).

## 5. Adapters and cost policy

- **fork** — in-process pipeline above, `--advisor on|off` → systems `s4-fork-on` /
  `s5-fork-off`, condition `blind` (the fork does its own retrieval; feeding it reference
  material would double-feed).
- **anthropic / openai** — model strings and params pinned in `tools/bench_config.yaml`,
  one item per request from `prompts/<condition>/<ITEM>.txt`, exponential-backoff retries.
  **Code-only for now: no API keys configured, never executed against the paid APIs; only
  `--dry-run` is exercised (user decision, zero spend).**
- **production-stub** — reserved adapter name for a future production deployment; refuses
  to run with an explanatory message, writes nothing.

Every run emits `manifest.json` in each target directory: adapter, system, condition,
model+params, ISO-8601 start/end, host, per-item statuses, fork git HEAD + dirty flag +
working-diff sha256 (fork adapter), and sha256 content-hashes of the item bank
(`items/*.yaml`), the benchmark grounding (`grounding/*.md`), the advisor grounding corpus,
and the snapshot file. (The parent repo has no commits, so content hashes stand in for git
SHAs of the item bank and grounding; the fork repo's HEAD is `ab01b54` with the advisor
integration uncommitted — hence the dirty-diff hash.)
