# Upload model.pt into the CHI@Edge container, then download results.csv back out

CHI@Edge containers are Zun containers, not full VMs, so there is no cloud-init/config-drive file injection like on bare metal or KVM nodes. There are really three ways to move files in and out, in order of reliability:

1. **Bake the file into the image** (best for something static like a model checkpoint): add `COPY model.pt /app/model.pt` to the Dockerfile, push the image, and reference it in `container.create_container(image=...)`. This is the most robust option because it doesn't depend on the container staying reachable after boot.
2. **SSH-enabled container + `scp`**: if you built the container with an SSH server exposed on port 22 and a floating IP attached (see the "SSH-enabled container" pattern), you can just `scp` in and out like any normal host.
3. **`zun cp`**: Zun (the container service backing CHI@Edge) supports copying files into/out of a running container without SSH, similar to `docker cp`. python-chi does not consistently expose a high-level wrapper for this across versions, so the safe path is to shell out to the `zun` CLI (or call the Zun client's `copy` operation directly) rather than assume a `chi.container.upload()`/`download()` helper exists — I'd verify against your installed python-chi version before relying on it.

Below is the SSH/`scp` approach, which is the one I'm most confident works end-to-end today, combined with `zun cp` as a fallback if you don't want to expose SSH.

```python
import subprocess
import chi
from chi import container

chi.use_site("CHI@Edge")

container_ref = "my-container"  # name or uuid of the running container

# Option A: container has SSH + floating IP already
floating_ip = "129.114.xxx.xxx"
subprocess.run(["scp", "model.pt", f"root@{floating_ip}:/app/model.pt"], check=True)
# ... run your job inside the container ...
subprocess.run(["scp", f"root@{floating_ip}:/app/results.csv", "./results.csv"], check=True)

# Option B: no SSH needed, use Zun's native copy (via OpenStack CLI)
subprocess.run(["zun", "cp", "model.pt", f"{container_ref}:/app/model.pt"], check=True)
subprocess.run(["zun", "exec", container_ref, "python", "run_inference.py"], check=True)
subprocess.run(["zun", "cp", f"{container_ref}:/app/results.csv", "results.csv"], check=True)
```

If you're doing this repeatedly, baking `model.pt` into the image and only using `zun cp`/`scp` for the output `results.csv` is the cleanest split.
