```python
import chi
from chi import lease

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

reservations = []
lease.add_device_reservation(reservations, count=1, machine_name="raspberrypi4-64")

start_date, end_date = lease.lease_duration(hours=2)

pi_lease = lease.create_lease("my-pi-lease", reservations, start_date=start_date, end_date=end_date)
lease.wait_for_active(pi_lease["id"])

print("Lease active:", pi_lease["id"])
```

`add_device_reservation` builds a device-type reservation (as opposed to `add_node_reservation`, which is for bare-metal nodes on CHI@TACC/UC) — `machine_name="raspberrypi4-64"` targets the 64-bit Raspberry Pi 4 device type. `lease_duration(hours=2)` gives you correctly formatted start/end timestamps starting roughly now. `wait_for_active` blocks until Blazar has actually granted the reservation rather than just accepted the request, which matters because CHI@Edge Pis are a shared, often-contended pool and the lease can sit in a pending state if none are free right now.
