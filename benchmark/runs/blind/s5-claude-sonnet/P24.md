For Sense HAT work specifically, launch the container with the `sense_hat` device profile — that's what exposes the relevant I2C devices from the host into the container. If you need raw GPIO pins beyond what the Sense HAT profile covers, look for a separate GPIO-oriented device profile on the specific device type you're targeting (not every CHI@Edge device type exposes the same set of profiles — availability depends on the physical hardware attached to that unit).

For the image: CHI@Edge runs containers (Zun), not whole-disk OS images, so you need a container image rather than something like a `CC-Ubuntu` bare-metal image. Pick a base that:
- matches the target device's CPU architecture (arm64/aarch64 for a Raspberry Pi 4),
- has Python plus the `sense_hat` package (and its I2C/RTIMULib dependencies) installed, or `RPi.GPIO`/`gpiozero` if you're doing general GPIO work.

There isn't a single official "the" Sense HAT image name I can point you to reliably — most people either build a small custom image (Dockerfile based on a `python:*-slim` arm64 variant with `pip install sense_hat`) or use whatever example image is currently listed in the CHI@Edge tutorials for that device.

To confirm the exact, currently-valid profile and image options rather than relying on a possibly-stale name:

```python
import chi
from chi import container

chi.use_site("CHI@Edge")

# See what device profiles exist right now
for p in container.list_device_profiles():
    print(p)

# See what device types exist and cross-reference which ones carry a Sense HAT
for d in container.list_device_types():
    print(d)
```

Cross-check against the device's entry in the Chameleon Hardware Browser, which lists the device profiles that specific unit supports — attaching a profile the device doesn't actually support will simply fail to schedule.
