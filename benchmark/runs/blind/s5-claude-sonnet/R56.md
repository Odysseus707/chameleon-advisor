For running an int8-quantized TFLite model specifically **on an Edge TPU**, only one CHI@Edge device type actually has that hardware:

1. coral-dev — the only CHI@Edge device type that carries a Coral Edge TPU (the ASIC the pycoral / tflite-runtime Edge TPU delegate targets). This is the only board that can literally execute your model on the Edge TPU as requested.

I don't have a legitimate #2 or #3 here. None of the other CHI@Edge device types (raspberrypi4-64, raspberrypi5, jetson-nano, jetson-xavier-nx-devkit-emmc, jetson-orin-nano-devkit-nvme, jetson-agx-orin-devkit-64gb) include a Coral Edge TPU, so an int8 TFLite model run on any of them would execute on CPU (or, on the Jetsons, on GPU/TensorRT after conversion) rather than on an Edge TPU. If coral-dev isn't available for your window, your real options are to wait for a coral-dev reservation, or to drop the "Edge TPU" requirement and accept CPU-only TFLite inference on a Raspberry Pi — that is a different execution path, not true Edge TPU acceleration.
