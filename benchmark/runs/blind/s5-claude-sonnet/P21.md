On CHI@Edge, hardware access (like a Sense HAT) is granted through a **device profile** when you launch a Zun container — there's no separate OS-install step like on CHI@UC bare metal. The general workflow is:

1. Switch to the CHI@Edge site in python-chi.
2. If the device you want requires an explicit reservation, reserve it with `chi.lease.add_device_reservation` (CHI@Edge uses Blazar device leases, distinct from the `add_node_reservation` used for bare-metal nodes). Some shared/community edge devices can also be scheduled to directly without a lease step — check the Hardware Browser for the device you're targeting.
3. Create the container with `device_profiles=["sense_hat"]`, which exposes the Sense HAT's I2C bus/devices into the container.
4. Use a container image (not a whole-disk OS image) that has the `sense_hat` Python package (or at least `smbus`/I2C tooling) installed, built for the device's architecture (arm64 for Raspberry Pi 4).

```python
import chi
from chi import container, lease

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

# 1. Reserve a device (confirm the exact machine_name for a Sense HAT-equipped
#    device via chi.container.list_device_types() or the Hardware Browser)
reservations = []
lease.add_device_reservation(
    reservations,
    count=1,
    machine_name="raspberrypi4-64",
)
device_lease = lease.create_lease("sense-hat-lease", reservations)
lease.wait_for_active(device_lease["id"])
reservation_id = device_lease["reservations"][0]["id"]

# 2. Launch the container with the sense_hat device profile
my_container = container.create_container(
    name="sense-hat-demo",
    image="python:3.9-slim",       # replace with an image that has sense_hat installed
    device_profiles=["sense_hat"], # exposes the Sense HAT's I2C devices to the container
    reservation_id=reservation_id,
    command=["sleep", "infinity"],
)

container.wait_for_active(my_container.uuid)
print(container.show_container(my_container.uuid))
```

A couple of things I can't fully confirm without checking the live catalog, so verify before you run this: the exact `machine_name` string for a Sense HAT-carrying device, and whether your project's CHI@Edge deployment currently requires the explicit device-lease step at all versus scheduling straight from `create_container`. Run `chi.container.list_device_profiles()` and `chi.container.list_device_types()` to confirm current names.
