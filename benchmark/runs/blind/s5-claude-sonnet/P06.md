```python
import chi
from chi import container

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

my_container = container.create_container(
    "my-container",
    image="ubuntu",
    reservation_id=reservation_id,
    command=["sleep", "infinity"],
)

container.wait_for_active(my_container.uuid)

# Now you can exec into it
result = container.execute(my_container.uuid, "bash -c 'echo hello'")
print(result)
```

The exit-immediately behavior is standard Docker semantics, not a CHI@Edge quirk: a base `ubuntu` image's default entrypoint has nothing to keep the container's PID 1 alive once it runs, so the container transitions straight from running to exited. Giving it an explicit long-running foreground command — `sleep infinity` is the simplest — keeps PID 1 alive indefinitely so the container stays in a running state and you can `container.execute()`/exec into it whenever you like. `tail -f /dev/null` is an equally common alternative if you want something slightly more conventional-looking in logs.
