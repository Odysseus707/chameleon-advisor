Since you only need CPU-based TFLite inference (no GPU/accelerator required) for about 4 hours on 1 device, most CHI@Edge device types can technically run this. I'm ranking by how well-suited and well-documented each is for this specific workload, not by raw capability:

1. raspberrypi4-64 — a very common, well-documented CHI@Edge platform for exactly this workload (MobileNet TFLite CPU classification is one of the standard example workloads); its ARM Cortex-A72 CPU is sufficient for MobileNet-class models at modest throughput.
2. raspberrypi5 — noticeably faster CPU than the Pi 4, giving more headroom for lower per-image latency; otherwise equivalent for this task.
3. jetson-nano — its CPU can run MobileNet TFLite without touching the GPU, but the device is normally reserved for GPU-accelerated (TensorRT) workloads, so treat this as a fallback if only Jetson capacity is free, given you're deliberately not using the GPU here.

I'm not confident about raw CPU-only inference throughput on jetson-xavier-nx-devkit-emmc, jetson-orin-nano-devkit-nvme, jetson-agx-orin-devkit-64gb, or coral-dev relative to the Pi boards, so I won't rank them — they would likely work but I can't say how well without live benchmark data.

# Example: run MobileNet TFLite classification on CPU
import numpy as np
import tflite_runtime.interpreter as tflite

interpreter = tflite.Interpreter(model_path="mobilenet_v1_1.0_224_quant.tflite")
interpreter.allocate_tensors()

input_details = interpreter.get_input_details()
output_details = interpreter.get_output_details()

# input_data should be a preprocessed uint8/float32 image array
# matching input_details[0]['shape']
interpreter.set_tensor(input_details[0]['index'], input_data)
interpreter.invoke()
output_data = interpreter.get_tensor(output_details[0]['index'])
predicted_class = np.argmax(output_data)
