# Launch a container with the Pi camera enabled

For the container to see the camera, the device node(s) the camera exposes (e.g. `/dev/video0`, or the CSI-connected `/dev/vchiq`/`/dev/vcsm` on older Pi camera stacks) have to be passed through into the container — a plain Zun container is otherwise isolated from host devices. I'm not fully certain of the exact parameter name CHI@Edge uses for this in `container.create_container()` (I've seen device-passthrough handled in some Zun deployments via a `device_profiles` list, but I can't confirm CHI@Edge exposes a ready-made `camera` profile by that exact name without invented specifics), so treat the profile name below as something to verify against current docs rather than a guaranteed API.

```python
import chi
from chi import container

chi.use_site("CHI@Edge")

my_container = container.create_container(
    name="camera-container",
    image="youruser/edge-camera-arm64:latest",
    reservation_id=device_reservation_id,   # from a lease on a camera-equipped Pi
    exposed_ports=[22],
    device_profiles=["camera"],  # verify the exact profile name in current CHI@Edge docs
)
container.wait_for_active(my_container.uuid)
```

Two prerequisites regardless of the exact passthrough mechanism:

1. You need to have reserved a device that actually has a camera attached in the first place (see the separate question on finding camera-equipped Pis) — device passthrough doesn't help if the underlying hardware has none.
2. Your image needs the camera userspace stack for the reservation's platform (e.g. `libcamera-apps`/`raspistill`/`raspivid` matching the Pi's OS/firmware) so that once the device node is visible inside the container, something can actually talk to it.

If `device_profiles` isn't the right knob in the current python-chi/Zun version, the fallback most container platforms support is running the container privileged (`privileged=True`) so all host devices are visible — coarser and less desirable from a security standpoint, but a reasonable fallback to confirm camera access works before narrowing to a scoped device profile.
