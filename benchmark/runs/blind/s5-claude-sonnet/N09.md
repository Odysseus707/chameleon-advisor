# Camera-equipped Pi, camera container, then retrofit SSH for a teammate

Two things to get right here: (1) reserving a device that actually has a camera attached, and (2) adding SSH into a container that's already running rather than baking it in from the start.

## 1. Reserve a camera-equipped device and start the camera container

CHI@Edge lets you filter a device reservation by resource properties, not just machine type. Ask for a Pi with the camera capability:

```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")
chi.set("project_name", "<your-project>")

reservations = []
lease.add_device_reservation(
    reservations,
    count=1,
    machine_name="raspberrypi4-64",
    resource_properties=["==", "$camera", "true"],
)
start_date, end_date = lease.lease_duration(days=1)

my_lease = lease.create_lease("camera-pi-lease", reservations,
                               start_date=start_date, end_date=end_date)
lease_id = my_lease["id"]
lease.wait_for_active(lease_id)
reservation_id = lease.get_device_reservation(lease_id)

cam_container = container.create_container(
    "camera-container",
    image="<your-camera-capture-image>",
    reservation_id=reservation_id,
    exposed_ports=[22],           # reserve the port now even though sshd isn't running yet
    device_profiles=["camera"],   # grants /dev/video0 (or the CSI camera device) inside the container
)
container.wait_for_active(cam_container.uuid)
```

I'm not fully certain `resource_properties` filtering on device reservations is exposed identically to node reservations in every python-chi version — if it errors, fall back to browsing the CHI@Edge hardware listing for a specific camera-equipped node and reserve it by `device_name` instead of `machine_name`.

## 2. Retrofit SSH into the running container

Exec into it, install and configure sshd, drop in the public key, and enable root login:

```python
pub_key = open("/path/to/teammate_id.pub").read().strip()

setup_cmds = f"""
apt-get update && apt-get install -y openssh-server
mkdir -p /var/run/sshd /root/.ssh
echo "{pub_key}" >> /root/.ssh/authorized_keys
chmod 700 /root/.ssh && chmod 600 /root/.ssh/authorized_keys
sed -i 's/#PermitRootLogin.*/PermitRootLogin yes/' /etc/ssh/sshd_config
sed -i 's/#PubkeyAuthentication.*/PubkeyAuthentication yes/' /etc/ssh/sshd_config
/usr/sbin/sshd
"""
container.execute(cam_container.uuid, setup_cmds)

fip = container.associate_floating_ip(cam_container.uuid)
print("SSH in with: ssh root@" + fip)
```

Important caveat: **port exposure is set at container creation and I'm not aware of a way to add an exposed port to an already-running Zun container on CHI@Edge.** That's why the example above puts `22` in `exposed_ports` up front even though sshd isn't started until later — "retrofit" here means retrofitting the *service*, not the network path. If the camera container is already running without port 22 declared, the safe route is to recreate it with port 22 exposed and then run the sshd setup exec above; there's no reliable way to open a new port on a live container. Once the floating IP is associated and sshd is running, your teammate can SSH in directly as root using their key.
