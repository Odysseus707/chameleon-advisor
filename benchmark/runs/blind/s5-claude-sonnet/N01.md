```python
import base64
import chi
from chi import lease, container

chi.use_site("CHI@Edge")

# 1. Reserve one camera-capable Pi
reservations = []
lease.add_device_reservation(
    reservations, machine_name="raspberrypi4-64", count=1, device_profiles=["pi_camera"]
)
start_date, end_date = lease.lease_duration(hours=1)
l = lease.create_lease("camera-video-lease", reservations, start_date=start_date, end_date=end_date)
lease.wait_for_active(l["id"])
reservation_id = lease.get_device_reservation(l["id"])

# 2. Launch a container that has the camera device profile attached
c = container.create_container(
    "camera-video",
    image="your-camera-image",  # must have rpicam-apps / libcamera-apps installed
    reservation_id=reservation_id,
    device_profiles=["pi_camera"],
    exposed_ports=[22],
)
container.wait_for_active(c["uuid"])

# 3. Capture 10s of 720p video at 30fps, encoded directly to mp4
container.execute(
    c["uuid"],
    "rpicam-vid -t 10000 --width 1280 --height 720 --framerate 30 --codec libav -o /tmp/clip.mp4",
)

# 4. Pull the file back without needing SSH/a floating IP: base64 it over exec and decode locally
result = container.execute(c["uuid"], "base64 /tmp/clip.mp4")
with open("clip.mp4", "wb") as f:
    f.write(base64.b64decode(result["output"]))
```

Two things worth calling out: the container image itself has to include the camera userspace tools (`rpicam-apps`, the Bookworm-era rename of `libcamera-apps` — use `libcamera-vid` instead if your image is still Bullseye-based); and CHI@Edge containers don't give you a filesystem download button, so the exec+base64 round trip (or standing up SSH + a floating IP and using `scp`) is how you get the file back to your machine. For a 10-second 720p clip the base64 approach is fine; for larger files SSH/scp is more robust.
