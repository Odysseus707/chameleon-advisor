One caveat first: I'm not fully confident CHI@Edge's device catalogue currently includes "Raspberry Pi 5" as a machine type — the models I know for certain are Pi 3B+ and Pi 4. If Pi 5 nodes exist, the `machine_name` below is my best guess at the naming convention (`raspberrypiN-bitwidth`), but confirm the exact string against the CHI@Edge hardware browser before running this.

To reserve *any* free device of a given type (rather than a specific named unit), you request the reservation by `machine_name`/type only and let Blazar pick an available match — you don't pin a specific hostname:

```python
import chi
from chi import lease

chi.use_site("CHI@Edge")
# chi.set("project_name", "your-project-name")  # or export OS_PROJECT_NAME

reservations = []
lease.add_device_reservation(reservations, count=1, machine_name="raspberrypi5-64")  # verify exact type string in the hardware browser

start_date, end_date = lease.lease_duration(hours=3)

my_lease = lease.create_lease(
    "any-pi5-3h-lease",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date,
)
lease.wait_for_active(my_lease["id"])

print("Lease active:", my_lease["id"])
print("Reservation:", lease.get_device_reservation(my_lease["id"]))
```

`add_device_reservation` with only `machine_name` (no specific device name/UUID) reserves by type — Blazar assigns whichever matching Pi 5 unit is free for the requested window, which is what "any free Pi 5" means in practice. If no unit of that type is free for the next 3 hours, `create_lease`/`wait_for_active` will fail or the lease will sit non-active until a slot opens — check the CHI@Edge availability calendar for that machine type if the reservation doesn't go active immediately.
