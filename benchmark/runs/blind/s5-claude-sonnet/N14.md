I don't have confident, specific knowledge of an officially documented CHI@Edge "device profile" for USB audio/microphone passthrough the way there is one for the Pi camera. I'd rather say that plainly than invent a profile name — check the CHI@Edge hardware/device-profile documentation or the site's Slack/mailing list to confirm whether one exists before relying on this.

What I can say with more confidence is the general shape of the problem and the most likely path to get it working:

- CHI@Edge containers don't get arbitrary host device access by default; peripherals (camera, GPIO, etc.) are exposed through specific, curated device profiles requested at container-creation time, not through generic `--privileged` or manual `/dev` mounts. If USB audio isn't one of the profiles CHI@Edge currently supports, you likely can't get raw ALSA device access to a USB mic from inside a container without a profile for it.
- If a matching profile does exist (check the docs for something audio/USB-related), the pattern would look like this at container creation:

```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")

reservations = []
lease.add_device_reservation(reservations, count=1, machine_name="raspberrypi4-64")
start_date, end_date = lease.lease_duration(hours=2)

my_lease = lease.create_lease(
    "pi-usb-mic-lease",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date,
)
lease.wait_for_active(my_lease["id"])
reservation_id = lease.get_device_reservation(my_lease["id"])

my_container = container.create_container(
    "pi-usb-mic-recorder",
    image="python:3.9-slim",
    reservation_id=reservation_id,
    # device_profiles=["<check docs for the exact USB-audio profile name>"],
    public_ip=True,
)
container.wait_for_active(my_container.uuid)
```

Then, once the container actually has `/dev/snd` visible, recording would just be standard ALSA usage, e.g.:

```python
import subprocess

# List capture devices to confirm the USB mic is visible
subprocess.run(["arecord", "-l"])

# Record 10 seconds from the default (or specified) capture device
subprocess.run([
    "arecord", "-D", "plughw:1,0", "-f", "S16_LE", "-r", "44100",
    "-d", "10", "recording.wav",
])
```

Bottom line: the recording code itself is standard `arecord`/ALSA and not Chameleon-specific, but whether it will actually see the USB microphone depends entirely on whether CHI@Edge exposes a device profile for USB audio devices — I can't confirm that one exists, so verify against current CHI@Edge docs before building on this.
