Scan the I2C bus with `i2cdetect` (from the `i2c-tools` package). Bus 1 is the standard I2C bus exposed on the Raspberry Pi header, which is what the Sense HAT sits on.

```python
import subprocess

result = subprocess.run(
    ["i2cdetect", "-y", "1"],
    capture_output=True, text=True,
)
print(result.stdout)
```

If `i2cdetect` isn't available in the container, install `i2c-tools` first (`apt-get update && apt-get install -y i2c-tools`, assuming the image has apt and you have permission to install packages inside the container).

If you'd rather avoid shelling out, you can scan addresses directly in Python with `smbus2`:

```python
import smbus2

bus = smbus2.SMBus(1)
found = []
for addr in range(0x03, 0x78):
    try:
        bus.read_byte(addr)
        found.append(hex(addr))
    except OSError:
        pass
print("Devices found at:", found)
```

A couple of debugging notes:
- If the scan comes back empty, the most common cause on CHI@Edge is that the container wasn't launched with the device profile that exposes `/dev/i2c-1` (e.g. `sense_hat`) — the bus simply isn't visible from inside the container otherwise.
- I won't guess the exact hex addresses you should expect to see, since that depends on which Sense HAT revision is attached and which chips are populated — treat whatever `i2cdetect` reports as ground truth rather than a fixed list.
