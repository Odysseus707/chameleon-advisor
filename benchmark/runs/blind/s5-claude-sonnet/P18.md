Recording 5 seconds of 1080p video, run inside the container once it has camera device access wired up via a device profile at container-creation time:

```python
import time
from picamera2 import Picamera2
from picamera2.encoders import H264Encoder

picam2 = Picamera2()
video_config = picam2.create_video_configuration(main={"size": (1920, 1080)})
picam2.configure(video_config)

encoder = H264Encoder(bitrate=10000000)
picam2.start_recording(encoder, "video_1080p.h264")
time.sleep(5)
picam2.stop_recording()
```

That produces a raw H.264 elementary stream. If you want a playable `.mp4` container instead of the raw stream, mux it afterward with `ffmpeg` (if available in the container image):

```python
import subprocess

subprocess.run([
    "ffmpeg", "-y", "-r", "30", "-i", "video_1080p.h264",
    "-c", "copy", "video_1080p.mp4",
])
```

To get the file off the device, the approach I'm confident works is serving it over HTTP from the container and pulling it with a normal client (same pattern as retrieving a still image) — I don't have confident, up-to-date knowledge of an exact `zun`/`openstack appcontainer cp`-style single-file-copy command for CHI@Edge, so I'd rather not guess at that syntax:

```python
import http.server
import socketserver

with socketserver.TCPServer(("", 8000), http.server.SimpleHTTPRequestHandler) as httpd:
    httpd.serve_forever()
```

```bash
curl -O http://<container-floating-ip>:8000/video_1080p.mp4
```

Requires the container to have been created with `exposed_ports=[8000]` and `public_ip=True`. Also note: `time.sleep(5)` gives an approximate 5-second clip length; for a frame-accurate duration you'd instead count frames or use picamera2's recording duration handling rather than a plain sleep.
