I can give you a confident answer for the container/OpenCV side, but I want to flag a real gap on the "device profile" side rather than invent a name.

What I know for certain about CHI@Edge camera access: containers are launched through Zun, and the documented mechanism for getting camera hardware into a container is the `device_profiles` argument on `container.create_container()`, e.g. `device_profiles=["camera"]`. That's the pattern shown in Chameleon's own edge computer-vision examples, and it's built around the Raspberry Pi's CSI camera module.

What I'm not sure of: whether CHI@Edge exposes a *separate* device profile specifically for generic USB/UVC webcams, as opposed to the CSI camera. I don't want to guess a profile name I can't confirm. If there isn't a distinct "usb-camera" profile, a plain UVC webcam typically just shows up as a standard `/dev/video0` USB device on the host, and whether your container can see it depends on whether Zun grants the container access to host USB device nodes for that device profile — which I can't verify from what I know. My genuine recommendation: request `device_profiles=["camera"]` first since it's the one documented profile, and if the UVC webcam isn't visible inside the container, check the CHI@Edge device profile listing for the specific Pi you reserved (`openstack appliance ...` or the CHI@Edge portal's device catalog) rather than assuming a name.

Container setup for OpenCV once the device is visible:

```python
import chi
from chi import container

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

my_container = container.create_container(
    "cv-webcam",
    image="ubuntu",          # multi-arch image; Zun pulls the arm64/armhf variant on the Pi
    reservation_id=reservation_id,
    device_profiles=["camera"],
    command=["sleep", "infinity"],
)

container.wait_for_active(my_container.uuid)

# Inside the container, install OpenCV and its runtime deps:
setup_cmd = (
    "apt-get update && "
    "apt-get install -y python3-pip libgl1 libglib2.0-0 v4l-utils && "
    "pip3 install opencv-python-headless"
)
container.execute(my_container.uuid, f"bash -c '{setup_cmd}'")

# Sanity check the device node and that OpenCV can open it
container.execute(my_container.uuid, "ls -l /dev/video0")
container.execute(
    my_container.uuid,
    "python3 -c \"import cv2; cap = cv2.VideoCapture(0); print(cap.isOpened())\"",
)
```

`opencv-python-headless` is the right variant for a container without a display server. `v4l-utils` is handy for confirming the webcam enumerates correctly (`v4l2-ctl --list-devices`) before you debug OpenCV itself.
