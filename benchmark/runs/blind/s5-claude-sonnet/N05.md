```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")

reservations = []
lease.add_device_reservation(reservations, machine_name="raspberrypi4-64", count=3)
start_date, end_date = lease.lease_duration(hours=6)
l = lease.create_lease("triple-pi-lease", reservations, start_date=start_date, end_date=end_date)
lease.wait_for_active(l["id"])
reservation_id = lease.get_device_reservation(l["id"])

c = container.create_container(
    "ssh-pi-container",
    image="your-ssh-enabled-image",  # must run sshd and allow root login itself
    reservation_id=reservation_id,
    exposed_ports=[22],
)
container.wait_for_active(c["uuid"])

container.associate_floating_ip(c["uuid"])
```

One reservation with `count=3` gets you the three devices under a single lease and a single `reservation_id`. The container step launches one container against that reservation (as asked) — it lands on one of the three reserved Pis; if you want containers running on all three you'd call `create_container` two more times against the same `reservation_id`.

The root-SSH part needs a real caveat: CHI@Edge containers are not VMs and don't come with an SSH daemon by default. There's nothing python-chi can flip to "enable SSH" — the image itself has to run `sshd`, allow root login (`PermitRootLogin yes` or key-based, not password-only in practice), and have your public key or a root password baked in or supplied via an environment variable/entrypoint script, in addition to opening port 22 via `exposed_ports` and attaching a floating IP so it's reachable from outside. If your image doesn't already do this, you'd need to build one that does before this will actually give you a login prompt.
