On CHI@Edge, you reserve hardware through the same Blazar lease mechanism used elsewhere on Chameleon, but with a *device* reservation instead of a *node* reservation. There are two ways to target hardware:

- `machine_name` (or `device_type` in older docs) reserves any device of a given type — you don't control which physical unit you get.
- `device_name` reserves one specific, named physical device.

Since you want the one physical unit that has a Sense HAT wired to it, you need `device_name`, not `machine_name`. Find the exact device name first — the Chameleon Hardware Browser (chameleoncloud.org/hardware, filtered to the CHI@Edge site) lists each device's name along with the `device_profiles` it supports (look for `sensehat` in the profile list), or the CLI/API device listing shows the same thing.

```python
import chi
from chi import lease

chi.use_site("CHI@Edge")

# Look this up in the CHI@Edge hardware browser first -- filter devices
# by the "sensehat" device_profile and copy the exact device name.
device_name = "iot-rpi4-sensehat-01"  # <-- replace with the real device name

reservations = []
lease.add_device_reservation(reservations, count=1, device_name=device_name)

start_date, end_date = lease.lease_duration(days=1)

my_lease = lease.create_lease(
    "sensehat-device-lease",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date,
)
lease.wait_for_active(my_lease["id"])
print(my_lease["id"])
```

I don't know the real device name off the top of my head — it will be a site-specific string you have to pull from the hardware browser or device listing, not something to guess. Reserving by `device_name` guarantees you get that exact physical board; reserving by `machine_name="raspberrypi4-64"` (or whatever the board's type is) would only guarantee a device of that *type*, which may or may not have a Sense HAT attached.
