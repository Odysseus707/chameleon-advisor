# Find which Pis have a camera attached and reserve one

I don't have confident, specific knowledge of the exact device names or a documented device-attribute flag (e.g. something like `has_camera`) that Blazar exposes for filtering CHI@Edge device reservations by "camera attached" — I don't want to invent a filter property that may not exist.

What I'd actually do:

1. **Check the Chameleon Hardware Discovery / hardware browser** (chameleoncloud.org's hardware catalog, filtered to the CHI@Edge site) — device pages there list each Pi's attached peripherals, including whether a Camera Module is connected, along with its `machine_name`/`device_name`. This is the authoritative source for which specific devices have a camera, since it's not something a generic Raspberry Pi model implies (some CHI@Edge Pis are camera-equipped, most aren't).
2. Once you have the specific `device_name`(s) from that listing, reserve by name rather than by generic model, since filtering by `machine_name="raspberrypi4-64"` alone will match camera-less Pis too:

```python
import chi
from chi import lease

chi.use_site("CHI@Edge")

reservations = []
# Reserve a specific device by name once you've identified a camera-equipped
# Pi from the CHI@Edge hardware browser.
lease.add_device_reservation(reservations, count=1, device_name="iot-rpi4-camera-01")

start_date, end_date = lease.lease_duration(days=1)
edge_lease = lease.create_lease("camera-lease", reservations,
                                 start_date=start_date, end_date=end_date)
lease.wait_for_active(edge_lease["id"])
```

The `device_name="..."` value above is a placeholder — substitute the actual name shown for a camera-equipped device on the hardware browser. If python-chi in your version doesn't support reserving by exact `device_name` (only by `machine_name`/model), the fallback is to reserve by model and then check `lease.get_device_reservation` / device details after the fact to confirm you landed on a camera-equipped unit, retrying if not.
