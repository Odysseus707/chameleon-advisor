Two complementary ways to do this:

**1. List all device profiles and cross-reference against the device's hardware entry.** `device_profiles` aren't tied 1:1 to a device type in the API response itself (a profile like `sense_hat` only makes sense on devices that physically have a Sense HAT wired up), so you list what profiles exist, then check which device types the Hardware Browser lists as supporting each one:

```python
import chi
from chi import container

chi.use_site("CHI@Edge")

# All device profiles currently defined on CHI@Edge
for p in container.list_device_profiles():
    print(p)

# All device types, so you can match profile <-> device type by hardware spec
for d in container.list_device_types():
    print(d)
```

**2. Check the Hardware Browser entry for the specific device.** On the Chameleon portal, Discover > Hardware Browser > CHI@Edge, open the device (or device type) you care about — its spec page lists the device profiles that unit supports, which is generally the more trustworthy source since it reflects what's physically attached to that hardware rather than just what profiles exist in the catalog.

If you attach a profile a device doesn't actually support, `create_container` will simply fail to schedule rather than silently ignoring it, which is also a (blunt) way to find out empirically.
