Sticking strictly to the classic imperative `python-chi` API — plain module-level functions from `chi.lease` and `chi.container`, no `Lease`/`Container` object classes:

```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")
# chi.set("project_name", "your-project-name")  # or export OS_PROJECT_NAME

# 1. Reserve one Pi 4 for 10 hours, starting now
reservations = []
lease.add_device_reservation(reservations, count=1, machine_name="raspberrypi4-64")
start_date, end_date = lease.lease_duration(hours=10)

my_lease = lease.create_lease(
    "pi4-ssh-lease",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date,
)
lease.wait_for_active(my_lease["id"])
reservation_id = lease.get_device_reservation(my_lease["id"])

# 2. Launch python:3.9-slim, install and start SSH, expose port 22 with a public IP
ssh_bootstrap = (
    "apt-get update && "
    "apt-get install -y openssh-server && "
    "mkdir -p /run/sshd && "
    "echo 'root:ChangeThisPassword123' | chpasswd && "
    "sed -i 's/#PermitRootLogin prohibit-password/PermitRootLogin yes/' /etc/ssh/sshd_config && "
    "sed -i 's/#PasswordAuthentication yes/PasswordAuthentication yes/' /etc/ssh/sshd_config && "
    "/usr/sbin/sshd -D"
)

my_container = container.create_container(
    "pi4-python-ssh",
    image="python:3.9-slim",
    reservation_id=reservation_id,
    exposed_ports=[22],
    public_ip=True,
    command=["sh", "-c", ssh_bootstrap],
)
container.wait_for_active(my_container.uuid)

c = container.get_container(my_container.uuid)
print("Status:", c.status)
print("Public address:", c.addresses)
```

Connect once it's active:

```bash
ssh root@<floating-ip-from-addresses>
```

Notes:
- `machine_name="raspberrypi4-64"` targets the arm64 Pi 4 device type; if your site labels it differently (e.g. a 32-bit variant), check the CHI@Edge hardware listing for the exact `machine_name` string.
- Setting a root password with `chpasswd` inside a startup command is functional but not great practice — for anything beyond a quick test, bake an SSH public key into the image or an `authorized_keys` file instead of a hardcoded password.
- `exposed_ports=[22]` plus `public_ip=True` is what makes the container reachable from outside; without both, it stays on the internal network only.
