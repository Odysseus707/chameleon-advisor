The main constraint for this task isn't compute, it's hardware: a "Pi camera module" attaches via a CSI camera connector, and support for it is best (and best documented) on actual Raspberry Pi boards.

1. raspberrypi4-64 — has the native Raspberry Pi CSI camera connector and is the most commonly used, best-documented CHI@Edge device for Pi Camera Module workloads; the libcamera/picamera2 stack is well exercised there.
2. raspberrypi5 — same native CSI camera connector and current camera software stack; a solid alternative to the Pi 4 if that one isn't available.
3. jetson-nano — its CSI connector is physically compatible with the same Pi Camera Module v2 (IMX219) sensor, but I'm not confident the CHI@Edge Jetson Nano image is pre-configured for it out of the box, so treat this only as a fallback and confirm camera support before relying on it.

Device types without a standard Pi-camera-compatible CSI connector won't work for this task at all, regardless of compute power.

```python
# Example: capture a still with picamera2 on a Raspberry Pi (CHI@Edge)
from picamera2 import Picamera2
import time

picam2 = Picamera2()
picam2.start()
time.sleep(2)  # let auto-exposure settle
picam2.capture_file("still.jpg")
picam2.stop()
```
