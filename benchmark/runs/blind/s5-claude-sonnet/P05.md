```python
import chi
from chi import container

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

my_container = container.create_container(
    "my-ubuntu-container",
    image="ubuntu",
    reservation_id=reservation_id,  # from your active device lease
)

container.wait_for_active(my_container.uuid)
print("Container running:", my_container.uuid)
```

`reservation_id` here is the device reservation id from a lease you've already created and waited to go active on the reserved Pi (see the lease steps for CHI@Edge). The `image="ubuntu"` reference is a normal Docker Hub multi-arch tag — Zun (the container service backing CHI@Edge) pulls the arm64/armhf variant automatically since the target is a Raspberry Pi, so you don't need to specify an arch-suffixed image yourself.

One thing to know going in: a bare `ubuntu` image with no explicit command has no long-running foreground process, so the container will start and then exit almost immediately once its default command finishes — that's expected Docker behavior, not a failure. If you want the container to stay up (e.g., to `exec` into it afterward), give it a long-running command such as `command=["sleep", "infinity"]`.
