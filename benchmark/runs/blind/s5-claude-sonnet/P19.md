To verify a camera is detected inside a CHI@Edge container, you need the container to have been launched with a camera `device_profile` attached (e.g. `camera` or a board-specific profile like `onboard_camera`/`usb_camera`), otherwise `/dev/video*` will never appear regardless of what you check.

Once the container is running, run a command inside it (CHI@Edge containers are Zun containers — you don't SSH in by default, you execute commands against the container object via python-chi, or use `zun exec` from the CLI). Check for the video device node and, if `v4l-utils` is installed in the image, use `v4l2-ctl` for a proper device description.

```python
from chi import container

# `c` is the container object/reference returned by container.create_container(...)

# 1. Cheapest check: does the device node exist?
result = container.execute(c.uuid, "ls -la /dev/video*")
print(result)

# 2. Better check: ask the kernel what it thinks the device is
#    (requires v4l-utils in the container image; install if missing)
result = container.execute(c.uuid, "v4l2-ctl --list-devices")
print(result)

# 3. If neither v4l-utils nor /dev/video* show anything, the container
#    almost certainly wasn't launched with the camera device_profile
#    attached -- check container.create_container(..., device_profiles=[...])
```

If `/dev/video*` is missing entirely, the fix is almost always at container-launch time (missing `device_profiles` entry), not something you can resolve from inside a running container — device passthrough is fixed at container creation.
