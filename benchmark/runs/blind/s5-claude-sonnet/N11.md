Two caveats before the code: (1) I can't verify that a device literally named `nyu-rpi5-03` is registered on CHI@Edge, or that CHI@Edge currently offers Raspberry Pi 5 as a device type at all — the catalogue I'm confident about is Pi 3B+ and Pi 4. If that exact `machine_name` doesn't exist, the reservation call will simply fail (no matching device), so verify the name in the CHI@Edge hardware browser first. (2) `jupyter/minimal-notebook` is an x86/arm64 multi-arch image, so it should run on a Pi's arm64 container runtime, but confirm an arm64 build is being pulled.

With those caveats, here's the python-chi workflow (no Horizon) — reserve the named device for 2 hours, wait for the lease, then launch the Jupyter container with port 8888 exposed and a public (floating) IP:

```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")
# chi.set("project_name", "your-project-name")  # or export OS_PROJECT_NAME

# 1. Reserve the specific device for 2 hours
reservations = []
lease.add_device_reservation(reservations, count=1, machine_name="nyu-rpi5-03")
start_date, end_date = lease.lease_duration(hours=2)

my_lease = lease.create_lease(
    "nyu-rpi5-03-jupyter-lease",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date,
)
lease.wait_for_active(my_lease["id"])
reservation_id = lease.get_device_reservation(my_lease["id"])

# 2. Launch the Jupyter minimal-notebook container with a public IP
my_container = container.create_container(
    "jupyter-on-nyu-rpi5-03",
    image="jupyter/minimal-notebook",
    reservation_id=reservation_id,
    exposed_ports=[8888],
    public_ip=True,
)
container.wait_for_active(my_container.uuid)

c = container.get_container(my_container.uuid)
print("Container status:", c.status)
print("Addresses:", c.addresses)

# The Jupyter token is printed to the container's log on startup
print(container.get_logs(my_container.uuid))
```

Once the container is active, take the floating IP from `c.addresses` and browse to `http://<floating-ip>:8888/?token=<token-from-logs>`.
