CHI@Edge devices are reserved through Blazar the same way bare-metal nodes are on CHI@UC/TACC (a device reservation rather than a physical-host reservation), so checking availability follows the same "look at the calendar before you book" model — python-chi doesn't expose a single `is_device_free(name)` call.

Two practical options:

1. **Hardware Browser (recommended for a quick visual check).** On the Chameleon portal, go to Discover > Hardware Browser, filter to CHI@Edge, and open the specific device or device type. It shows the reservation calendar, so you can see at a glance whether it's currently held and when it frees up.

2. **Programmatically, via existing leases.** List current leases/reservations and check whether the device type's capacity is already consumed for the window you want:

```python
import chi
from chi import lease

chi.use_site("CHI@Edge")
chi.set("project_name", "YOUR_PROJECT_NAME")

for l in lease.list_leases():
    print(l["name"], l.get("reservations"))
```

This tells you what's already reserved, from which you can infer whether a unit of the device type you want is still free — it's not a direct "free right now" boolean, since Blazar reservations are about a future/current time window rather than a live occupancy flag.

If you just want to attempt the reservation and let the scheduler tell you, that also works: submitting a short `add_device_reservation` + `create_lease` will fail immediately if there isn't capacity, rather than sitting in a pending state — but that's a "try it and see" approach, not a true pre-check.
