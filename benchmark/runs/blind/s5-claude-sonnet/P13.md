# Which image and exposed port do I need for SSH on CHI@Edge?

Port: **22/tcp** — pass it in `exposed_ports=[22]` (or `["22/tcp"]` depending on your python-chi version) when you call `container.create_container(...)`, and make sure the security group covers inbound TCP 22 to the floating IP you attach.

Image: there isn't a single official "the SSH image" you're required to use — CHI@Edge just runs whatever OCI/Docker image you give it, and CHI@Edge devices (Raspberry Pi, Jetson, etc.) are **arm64**, so the image has to be built for `linux/arm64`. What matters functionally:

- `openssh-server` (or equivalent) installed and started as the container's foreground process (`CMD ["/usr/sbin/sshd", "-D"]` or similar), since the container needs a long-running foreground process to stay up.
- `PermitRootLogin yes` in `sshd_config` if you want root login (most distro defaults disable it).
- An entrypoint that writes an injected public key to `~/.ssh/authorized_keys` (see the separate question on key injection), since there's no cloud-init on CHI@Edge to do this for you.
- Prefer a glibc-based arm64 distro (e.g. Debian/Ubuntu arm64v8) over Alpine if you plan to attach tooling like VS Code Remote-SSH later — its remote server binary expects glibc and breaks on musl-based Alpine images.

I don't have a specific pre-built Chameleon-maintained SSH image name to hand you with confidence — if the CHI@Edge tutorial repo/appliance catalog has a ready-made "ssh-server" appliance, use that; otherwise the safest route is building your own minimal arm64 Dockerfile along the lines above.

```python
import chi
from chi import container

chi.use_site("CHI@Edge")

my_container = container.create_container(
    name="my-ssh-container",
    image="youruser/edge-ssh-arm64:latest",
    reservation_id=device_reservation_id,
    exposed_ports=[22],
)
```
