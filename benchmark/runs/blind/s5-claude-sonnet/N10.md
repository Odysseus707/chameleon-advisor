# One container, two peripherals: camera + Sense HAT on iot-rpi4-picam3

Since you already know the exact node name, reserve it directly by `device_name` rather than by machine type — that guarantees you land on the physical Pi with both the camera and the Sense HAT attached, instead of a random device that only matches one capability.

```python
import chi
from chi import lease, container

chi.use_site("CHI@Edge")
chi.set("project_name", "<your-project>")

reservations = []
lease.add_device_reservation(
    reservations,
    count=1,
    device_name="iot-rpi4-picam3",
)
start_date, end_date = lease.lease_duration(days=1)

my_lease = lease.create_lease("picam3-lease", reservations,
                               start_date=start_date, end_date=end_date)
lease_id = my_lease["id"]
lease.wait_for_active(lease_id)
reservation_id = lease.get_device_reservation(lease_id)

combo_container = container.create_container(
    "camera-sensehat-container",
    image="<your-image-with-picamera2-and-sense-hat-libs>",
    reservation_id=reservation_id,
    device_profiles=["camera", "i2c"],  # camera bus + I2C bus (Sense HAT talks I2C)
    exposed_ports=[22],
)
container.wait_for_active(combo_container.uuid)
```

I'm not 100% certain `i2c` is the exact device-profile string CHI@Edge uses for I2C bus access (versus something like `generic_i2c` or a Sense-HAT-specific profile) — check the profile names listed against this device in the hardware catalog before relying on that string; the concept (one profile grants the CSI camera device, a separate one grants the I2C bus the Sense HAT sits on) should hold either way.

## Verifying each peripheral inside the container

Camera — list detected cameras:

```python
container.execute(combo_container.uuid, "libcamera-hello --list-cameras")
# or, if the image uses the older stack:
container.execute(combo_container.uuid, "vcgencmd get_camera")
```

Sense HAT / sensor bus — probe the I2C bus for the expected addresses (Sense HAT devices typically show up around 0x1c–0x6a depending on the specific sensor chip):

```python
container.execute(combo_container.uuid, "apt-get install -y i2c-tools && i2cdetect -y 1")
```

`i2cdetect -y 1` should print a grid with hex addresses; occupied addresses show up as numbers instead of `--`, confirming the Sense HAT's sensors (pressure, humidity, IMU) are visible on the bus. If either command errors with a missing device file (e.g. no `/dev/video0` or no `/dev/i2c-1`), the container didn't actually get the corresponding device profile and it's worth re-checking the `device_profiles` list against what the catalog exposes for this specific node.
