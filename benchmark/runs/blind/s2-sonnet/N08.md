1. Launch the container
Assuming serve-edge-vr gives you shell/SSH access to the Pi (or a CLI to run commands on it), pull and run the Jupyter minimal-notebook image. On a Pi 5 (ARM64), the official Jupyter Docker Stacks images support arm64, so this works fine:
bashdocker run -d \
  --name jupyter-notebook \
  -p 8888:8888 \
  jupyter/minimal-notebook:latest
If your lease platform exposes a "public IP" as a configuration flag rather than a raw docker run, it's usually one of:

A --network or -p 0.0.0.0:8888:8888 binding to expose beyond localhost
A platform-specific flag/field (e.g. --publish or a "make public" toggle in a lease manifest/YAML) that assigns an externally routable IP to the container

Since I don't know the specifics of your lease tooling (what CLI or manifest format serve-edge-vr uses), check its docs for the exact syntax — but the container itself just needs port 8888 bound to 0.0.0.0 and the platform's public-IP feature enabled.
2. Find the token URL in the logs
bashdocker logs jupyter-notebook
Look for a block like:
    To access the notebook, open this file in a browser:
        file:///home/jovyan/.local/share/jupyter/runtime/nbserver-7-open.html
    Or copy and paste this URL:
        http://127.0.0.1:8888/lab?token=abcdef1234567890...
Grab the ?token=... part. Then swap 127.0.0.1 for your container's public IP to access it remotely:
http://<public-ip>:8888/lab?token=abcdef1234567890...
Handy one-liner to pull just the URL:
bashdocker logs jupyter-notebook 2>&1 | grep "token="
A couple of notes:

If you restart the container, the token usually stays the same (it's tied to the config unless you regenerate it), but always re-check logs after a restart to be safe.
Exposing Jupyter on a public IP with just a token is convenient but not great security hygiene long-term — consider setting a password (jupyter notebook password inside the container) or putting it behind a reverse proxy with TLS if this isn't just a quick throwaway session.
