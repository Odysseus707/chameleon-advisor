That said, I can help you get this done yourself. Here's what the actual workflow looks like using the python-chi / chi client or the Blazar CLI, so you can run it from your own machine with your Chameleon credentials:
1. Create the lease (3 raspberrypi4-64 nodes, 6 hours)
Using the python-chi SDK:
pythonimport chi
from chi import lease

chi.use_site("CHI@Edge")

reservations = []
lease.add_device_reservation(
    reservations,
    machine_name="raspberrypi4-64",
    count=3
)

my_lease = lease.create_lease(
    lease_name="rpi4-lease",
    reservations=reservations,
    start_date=None,   # starts now
    end_date=None,     # set via duration below
)
Or via CLI with blazar:
bashblazar lease-create \
  --physical-reservation min=3,max=3,resource_properties='["==","$node_type","raspberrypi4-64"]' \
  --start-date "now" \
  --end-date "+6 hours" \
  rpi4-lease
2. Launch an SSH-enabled container on the reserved nodes
CHI@Edge uses Zun (container-as-a-service) rather than Nova VMs. You'd launch a container against the reservation like:
pythonfrom chi import container

my_container = container.create_container(
    name="ssh-rpi-container",
    image="your-registry/ssh-enabled-image:latest",
    reservation_id=my_lease["reservations"][0]["id"],
    exposed_ports=[22],
)
For SSH-as-root access, your container image needs sshd installed and root login enabled (e.g., PermitRootLogin yes in sshd_config), plus your public key baked in or injected at boot — CHI@Edge doesn't automatically inject keypairs into containers the way Nova does for VMs, so you'll want an image that pulls your key from user data or has it pre-embedded.
A few things worth checking before you run this:

CHI@Edge capacity for raspberrypi4-64 is often limited — worth checking the hardware browser/availability calendar first to confirm 3 are free for your desired window.
