There's no built-in extend_lease() helper in python-chi — you update the lease directly through the underlying Blazar client. Here's the pattern:
pythonimport chi
from chi.lease import get_lease
from chi.clients import blazar
from datetime import datetime, timedelta

chi.use_site('CHI@Edge')
chi.set('project_name', 'CH-XXXXXX')  # your project

# Look up your lease (by name or ID)
lease = get_lease('lease-my-container')  # or pass the lease ID directly

# New end time = current end_date + 2 hours
new_end = lease.end_date + timedelta(hours=2)

# Push the update to Blazar directly (Blazar wants "%Y-%m-%d %H:%M")
blazar().lease.update(
    lease.id,
    end_date=new_end.strftime("%Y-%m-%d %H:%M")
)

print(f"Extended lease {lease.name} to {new_end}")
Notes:

chi.lease.Lease doesn't expose an extend() method, so this goes straight to blazar().lease.update(), which is the OpenStack Blazar client python-chi wraps.
Blazar will reject the update if the underlying device isn't available for the extra 2 hours (edge devices are single-tenant, so if no one else has it reserved next it should go through).
If your lease is about to expire, do this now — Blazar generally won't let you extend a lease that's already TERMINATED, only one still ACTIVE.
If you don't know the lease name, use chi.lease.list_leases() or chi.lease.show_leases() to find its ID first.

If the update call throws a BlazarClientException about resource conflicts, that means the device is already reserved by someone else right after your current end time, and you won't be able to extend.
