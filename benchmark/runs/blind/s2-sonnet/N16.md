2. Find a Jetson-class device
CHI@Edge nodes are registered by machine_name (device type). Common Jetson types are things like jetson-nano, jetson-xavier-nx, or similar depending on what's currently in the testbed — availability changes, so check the CHI@Edge hardware browser (https://chi.edge.chameleoncloud.org/hardware/) for exact current names before reserving.
python# List available device types matching Jetson
reservations = []
lease.add_device_reservation(
    reservations,
    machine_name="jetson-xavier-nx",  # confirm exact name on the hardware page
    count=1
)
3. Create the lease
pythonfrom datetime import datetime, timedelta

start_date, end_date = lease.lease_duration(days=1)  # adjust as needed

edge_lease = lease.create_lease(
    lease_name="jetson-cuda-inference",
    reservations=reservations,
    start_date=start_date,
    end_date=end_date
)
lease.wait_for_active(edge_lease["id"])
4. Launch a CUDA-capable container
CHI@Edge uses Zun for containers, not raw VMs. You need a container image with CUDA/JetPack libraries already baked in — NVIDIA's L4T (Linux for Tegra) base images work well, e.g. nvcr.io/nvidia/l4t-base or a custom image built on top of it with your inference framework (PyTorch for Jetson, TensorRT, etc.).
pythonreservation_id = lease.get_device_reservation(edge_lease["id"])

my_container = container.create_container(
    name="jetson-inference",
    image="nvcr.io/nvidia/l4t-base:r35.2.1",   # swap for your inference image
    reservation_id=reservation_id,
    exposed_ports=[8888],
    command=["python3", "your_inference_script.py"],
    # device passthrough for GPU access — required for CUDA to work
    device_profiles=["gpu"],  # exact profile name may vary; check node's device_profile_name
)
Important caveat: whether GPU passthrough works depends entirely on how that specific Jetson node type is registered in CHI@Edge — some device profiles expose the GPU/CUDA runtime to the container by default, others need an explicit runtime="nvidia" equivalent or a device profile flag. Check the node's registration details in the hardware browser or openstack appliance list for the exact container image/runtime requirements for that machine type, since this differs across the Jetson Nano vs. Xavier NX vs. AGX Orin listings.
5. Verify and use it
pythoncontainer.wait_for_active(my_container.uuid)
