2. Launch the sensor container so GPIO/I2C work
The core problem with Sense HAT (B) type boards in containers is that /dev/gpiomem, /dev/i2c-1, and the devicetree overlay info (/proc/device-tree) aren't visible unless you explicitly pass them through. Waveshare's Sense HAT (B) uses I2C (not SPI) for most sensors, so the key devices are /dev/i2c-1 and /dev/gpiomem (or /dev/gpiochip0 on newer kernels with libgpiod).
A typical docker run that works:
bashdocker run -it --rm \
  --privileged \
  --device /dev/i2c-1 \
  --device /dev/gpiomem \
  --device /dev/gpiochip0 \
  -v /sys/class/gpio:/sys/class/gpio \
  -v /proc/device-tree:/proc/device-tree:ro \
  your-sensor-image:latest
Notes:

--privileged is the blunt-force fix if fine-grained --device flags don't fully cover it (some libraries probe /dev/mem too).
Mounting /proc/device-tree read-only is what fixes the "missing devicetree info" symptom — without it, libraries like RPi.GPIO/gpiozero that try to detect board revision/model can fail or misbehave.
If you're on Docker Compose instead:

yamlservices:
  sensor:
    image: your-sensor-image:latest
    privileged: true
    devices:
      - /dev/i2c-1
      - /dev/gpiomem
      - /dev/gpiochip0
    volumes:
      - /proc/device-tree:/proc/device-tree:ro
      - /sys/class/gpio:/sys/class/gpio
3. List what's on the I2C bus
Once you're inside the container (assuming i2c-tools is installed):
bashi2cdetect -y 1
For the Sense HAT (B), expect to see something like:

0x5c – pressure/temp sensor (e.g. QMP6988 or similar depending on revision)
0x1e – IMU / magnetometer
0x40 – RGB/light sensor
0x62 – gas sensor (if fitted)

(exact addresses vary by hardware revision — the scan will tell you definitively).
