# Benchmark results

Generated by `tools/report_results.py`. Every figure is derived from `items/` and the scored CSV at run time.

## 1. What the benchmark is

- **134 items** across 2 suites: core 50, reservation 84
- **1015 checker instances**, 22 distinct types
- **330 (item, condition) pairs**: blind 134, heldout 62, matched 95, uncovered 39
- checker groups: capability 358, feasibility 228, mechanism 115, safety 199, specifics 115
- reservation coverage: covered 48, uncovered 36

Gold admission: every item's own `gold_spec` must pass 100% of its own checkers (50/50 core, 84/84 reservation).

`s3-chatbot-noadv` vs `s4-chatbot-adv`: same documentation RAG, same `qwen2.5:32b`, same 2x P100 node, same prompts. The only difference is whether the advisor fires. Frontier models and the historical baseline are *not* in this table - different hardware makes them a reference ceiling, not a control.

## 5. Slide-ready

1. **Availability accuracy 37% → 66%** (+29.4 pp) when the advisor fires.
2. **Capability accuracy barely moves** (48.3% → 48.9%, +0.6 pp) — Blazar exposes device *state*, not device *capability*.
3. **That split was predicted in writing before the run** (`audit/advisor_architecture_decision.md`).
4. **On the 5 undocumented accelerator types the advisor stops helping** — the measured case for artifact ingestion.

## 6. Caveats

- **One model, one node.** `qwen2.5:32b` on 2x P100. No claim about other models.
- **Full-item PASS is strict**: every checker on an item must pass. Group rates are the informative measure.
- **P12, P27 excluded** from core deltas: the advisor gate cannot fire on them, so they are identical in both arms.
- **Uncovered-item ground truth is ours.** No artifact documents those 5 device types, so `capability_table.yaml` (hand-authored vendor specs) defines correctness there.
- **The fed conditions are paste-shaped, not RAG-shaped.** Feeding a ~10k-token artifact blob as the retrieval query is not what the deployed chatbot ever sees; those rows measure the model, not the pipeline.
- **Ollama context was raised to 20480** for the fed conditions; at the default 4096 every fed prompt would have been silently truncated. Blind rows (58-543 tokens) were unaffected.
- **`s1-chatbot` / `s2-sonnet` are not controls** — collected on the retired node against an unrecorded model.
